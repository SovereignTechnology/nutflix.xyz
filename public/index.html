Nutflix is a video network with no company in the middle. Videos are announced on Nostr, streamed from other people's computers, and the people who seed them are paid by the people who watch.

Released · free video
SovereignTechnology/nfx

The open standard, and the Rust engine that runs it

NFX is the rulebook underneath Nutflix, together with the software that proves the rules work. A creator publishes a signed description of a video on Nostr. Anyone can keep a copy and serve it. Before your player shows you anything, it checks every piece of the video against the creator's signed hashes, so nobody in the middle can swap what you are watching.

Free video works today on a public test network. Paying seeders for each chunk in ecash is written into the standard and is still being audited before it is switched on.

What's inside

  • The protocol documents, public domain, for anyone to build against
  • nfxd, a node with no screen that publishes and seeds video, on a server or at home
  • nfx-package, which turns an ordinary video file into verifiable, streamable segments
  • A browser player that verifies every file before it plays it
  • Rust
  • iroh
  • WebRTC
  • CMAF
  • Nostr

SovereignTechnology/nutflix-pear

The desktop app

Nutflix as an app you install. It looks like a video site you already know, with a home page, search, Shorts, channels, comments and playlists, but there is no company server behind it. Videos stream straight from other people's computers, and the people who watch pay the people who seed, a few sats at a time, as the video arrives.

Creators set the price and choose the mints they accept, and you see the price before you press Play. By default each payment is split 50/50 between the creator and the seeder. It is a demo: not something to trust with money you cannot afford to lose.

What's inside

  • The desktop app, with a built-in Cashu wallet and a Studio for publishing
  • A seeding switch: serve videos from your own disk and earn the seeder's share
  • Seeder and gateway programs for machines with no screen
  • The source of the web player, which plays free videos in a browser
  • TypeScript
  • Electron
  • Hypercore
  • Cashu
  • Nostr

Pre-alpha
SovereignTechnology/nutflix-runtime

The app with no download server

An experiment in shipping Nutflix without a website to download it from. You would install it from a pear:// link, and it would update itself from that same link, over the peer-to-peer Pear network.

It reuses the desktop app's code, so it speaks the same language as the seeders that are already out there. The plan is for it to play free videos, trade video with web browsers, seed what it plays and publish new videos. Nothing here runs yet: the design is written down and the first pieces are in.

What's inside

  • The design record, and the experiments that have to pass first
  • The worker: the part that moves video between peers
  • The desktop app's code, pinned to one exact version so the two stay compatible
  • Pear
  • Bare
  • HyperDHT

SovereignTechnology/nutflix-nsite

The web player, published on Nostr

A small tool that publishes the Nutflix web player as an “nsite”: a website whose files live on public file servers and whose table of contents is a signed Nostr event, instead of everything sitting on one web host. Once it is published, any nsite gateway can serve the player, so watching does not depend on our server staying up.

There is no app code here. It takes one exact build of the web player, uploads each file under its own hash, signs the list, and then checks that gateways hand back the same bytes. The site itself has not been published yet.

What's inside

  • A publish script that uploads, signs and announces, and asks before it signs anything
  • A verify script that checks every gateway serves exactly the pinned files
  • The pin: the build it publishes, file by file and hash by hash
  • Nostr
  • NIP-5A
  • Blossom
  • Node.js

How it fits

One set of rules, two programs, one network

The repositories are not competing versions of the same thing. They are layers, and each one leans on the one before it.

  1. 1 · The rules

    An open standard

    How a video is described, found, checked and paid for. Anyone can build software that follows it, without asking us.

    • The NFX documentsin nfx

  2. 2 · The software

    Two programs that follow them

    Written separately, in different languages, and tested against each other in both directions.

    • nfxdthe Rust node, in nfx
    • Nutflix desktopthe app, in nutflix-pear

  3. 3 · Watching

    Ways to watch

    Two work today and a third is on the way. They pull from the same network of seeders.

    • The desktop appreleased for Linux, from nutflix-pear
    • The web playerin a browser; nutflix-nsite is for publishing it on Nostr
    • The Pear apppre-alpha, in nutflix-runtime

They share one network. A free video seeded by nfxd plays in the desktop app and in a browser, and nfxd can fetch a video that the desktop app seeds. That is the point of writing the rules down first.

The idea

Buffer = money

Seeding a video costs disk and bandwidth. Nutflix pays for it directly, from the viewer to the seeder, with no subscription and no advertiser in between.

01

Buffer is a spend bar

How far ahead your player fetches is a spending decision. Pause the player and the payments stop. You only pay for video that actually arrives.

02

Pay as it arrives

Each piece of video that reaches your player is paid for with a tiny Cashu payment to the peer that served it. No invoices for things you did not watch.

03

50/50 by default

Each payment carries two locked sets of ecash, one for the creator and one for the seeder, so neither can take the other's share. Creators can change the split.

04

Nostr-native

Videos, seeder announcements, comments and playlists are signed Nostr events, not rows in somebody's database.

Open protocol

Thirteen documents, no gatekeepers

NFX is written down as a set of short documents. Six are frozen, which means software can rely on them not changing underneath it.

  • NFX-01Networks & versionsFrozen
  • NFX-02Catalog manifestFrozen
  • NFX-03Availability beaconsFrozen
  • NFX-04Scoped relay profileFrozen
  • NFX-05Segments & content integrityFrozen
  • NFX-06iroh transportFrozen
  • NFX-07Payments, open modeDraft
  • NFX-08Payments, licensed mode & vouchersDraft
  • NFX-09Split-mint extensionDraft
  • NFX-10Web transportDraft
  • NFX-11Registry & conformanceLiving
  • NFX-12HyperDHT transport (optional)Draft
  • NFX-16Seeder ratings (optional)Draft

NFX-13 to NFX-15 are reserved for documents that are not written yet. The spec text is public domain (CC0): anyone can build a player, a seeder, a relay, a mint or an indexer from these documents alone. Read them on GitHub.

Status

Where it stands

Honestly: free video works, and paid video is still an experiment.

Working

Free video, end to end

A creator publishes, seeders serve, and a desktop app or a plain browser plays. Playback keeps going from peers after the original source is gone. It runs on a public test network.

Released

You can try it now

The web player runs in a browser with nothing to install. The desktop app is released for Linux, and nfxd has Linux builds too.

Experimental

Paid video

The desktop app can pay seeders as a video arrives, but it has only been tested against local mints with fake Lightning, and no real payment is on record. In NFX, payments are specified and still being audited, and are not switched on.

Experimental software, in active development. Protocols, formats and APIs can change without notice, and no outside party has audited the desktop app. Cashu ecash is bearer money, and a mint can lose or withhold it. If you add a real mint to the desktop app, keep the balance small.
